That leaves schedule holes unfilled, wastes the cost of acquiring those patients in the first place, and turns recall into a wish instead of an operating system.

## Offer

## Process
1. Fit call: confirm specialty, overdue-list shape, communication rules, and booking workflow
2. Onboarding: collect an overdue-patient export, clean the list, and approve scripts
3. Launch: run the recall sequence by segment and track replies, bookings, and opt-outs
4. Weekly review: see booked appointments, blocked cases, and highest-value next actions
5. Iteration: tighten scripts, timing, and segmentation based on what actually rebooks patients

## FAQ
- **How do you handle patient data and access safely?**: We start with least-privilege exports and approved tools only. No broad inbox or billing access is required in the starter workflow. We can work under an NDA and follow a defined retention window.
- **What prerequisites do we need before this works?**: You need an exportable overdue-patient list, one person who can approve scripts and booking rules, and a clear way for booked patients to be marked back in your system or tracker.
- **How long does onboarding take?**: Usually 2-4 business days. We clean the first list, align on segments, finalize scripts, and set up the tracker before launching the first recall sequence.
- **Will you talk to patients or book directly?**: That depends on the workflow you approve. In the starter version we usually run approved outbound messages and track replies/bookings, while your team keeps final control of phone calls, clinical questions, and scheduling policies.
- **What is your retention policy?**: By default we retain only the active list, tracker, and latest reports needed to run the service. We can delete source exports on request or follow a fixed retention window you choose.
