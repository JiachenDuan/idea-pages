# ReleaseReady Desk for B2B SaaS

**For:** For 5-100 person B2B SaaS teams shipping customer-facing releases

## Hero
- Headline: Ship customer-facing releases without the docs, support, and rollout scramble
- Subheadline: We turn every launch into a clean release packet: docs delta, internal enablement brief, rollout notes, and a first-week issue digest.

## Pain
Most launch pain starts after engineering says the feature is done. Docs are stale, support finds out too late, customer success has no rollout notes, and sales keeps showing the old workflow. The result is confused customers, avoidable tickets, and senior people doing launch cleanup at the worst possible moment.

## Before
- Docs updates happen at the last minute or not at all
- Support learns about the release from confused customers
- Sales and CS use stale screenshots, notes, or demos
- Known issues and rollout risks live in Slack threads

## After
- A clear launch packet for every customer-facing release
- Docs delta tracked before launch day
- Support macros and known-issue notes ready in advance
- A first-week digest showing adoption friction and launch issues

## Process
1. 15-min fit call to confirm release cadence, ICP, and systems
2. Onboarding: gather current docs, release workflow, owners, and templates
3. For each release: intake the change, build the launch packet, route approvals, and prep support/CS
4. After launch: capture first-week issues, adoption friction, and recommended fixes in one digest

## FAQ
- **What access do you need?**: Usually read/write access to your docs workspace, a release tracker, and a place to draft support/customer-facing notes. No production access needed. We work with least-privilege access and can use an NDA.
- **What needs to be true for this to work?**: You need one named internal owner, a rough release calendar, and a product contact who can answer edge-case questions quickly. This works best when releases already have some planning, but the execution layer is messy.
- **How long does onboarding take?**: Usually 3-5 business days to learn your workflow, collect current docs/templates, and set up the launch packet format. After that, new releases follow the same system.
- **How do you handle retention and sensitive information?**: We keep only the working documents needed for active releases, follow your retention window when possible, and can delete drafts/artifacts on request after handoff.
- **Will you rewrite our whole docs site?**: No. The core offer is release operations, not a blank-check docs project. We define clear page/asset limits and flag larger docs work separately before it expands scope.
