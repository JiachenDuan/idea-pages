FAQ

What access do you need?
Usually read/write access to your docs workspace, a release tracker, and a place to draft support/customer-facing notes. No production access needed. We work with least-privilege access and can use an NDA.
What needs to be true for this to work?
You need one named internal owner, a rough release calendar, and a product contact who can answer edge-case questions quickly. This works best when releases already have some planning, but the execution layer is messy.
How long does onboarding take?
Usually 3-5 business days to learn your workflow, collect current docs/templates, and set up the launch packet format. After that, new releases follow the same system.
How do you handle retention and sensitive information?
We keep only the working documents needed for active releases, follow your retention window when possible, and can delete drafts/artifacts on request after handoff.
Will you rewrite our whole docs site?
No. The core offer is release operations, not a blank-check docs project. We define clear page/asset limits and flag larger docs work separately before it expands scope.
