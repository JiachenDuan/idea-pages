## Offer
DataImport Desk is a done-for-you import operations layer for vertical SaaS: we collect the source files, clean and normalize them, map fields into your schema, run a preflight/test import, and hand off a clean final checklist to your team.

### Included
- Source-file intake checklist and required-field review
- CSV cleanup: duplicate detection, formatting normalization, and basic row validation
- Field mapping into one destination schema with documented assumptions
- One test import or import-ready validation pass plus issue log
- Customer-ready summary of blockers, fixes needed, and next steps

### Not included
- Custom ETL builds, direct database migrations, or production engineering work
- Net-new schema design or product configuration consulting
- Ongoing customer success ownership after the import is accepted
- Claims about data correctness beyond the provided source files and agreed rules

## Process
1. Fit call: confirm source system, destination schema, volume, and SLA
2. Onboarding: collect sample export, required fields, and import success criteria
3. Cleanup + mapping: normalize rows, flag exceptions, and document field rules
4. Validation: run a test import or preflight check and produce a short blocker list
5. Handoff: your team approves the final file and sends the customer the go-live next steps

## FAQ
- **How do you handle security and customer data access?**: We work from least-privilege shared folders or exports, not production credentials. Access can be time-boxed, NDA-backed, and limited to the exact files needed for the import.
- **What has to be true before we start?**: You need one destination schema, one named internal owner, and a sample source export or clear file format. We start with CSV-based workflows first, not direct database migrations.
- **What does onboarding look like?**: Usually one short kickoff, a source-file intake checklist, and agreement on required fields and import success criteria. After that, most communication happens through a simple blocker list and approval loop.
- **What is your retention policy?**: By default, we keep working files only for the active engagement window plus a short agreed retention period, then delete them. If you need a stricter retention window, we can set that up up front.
